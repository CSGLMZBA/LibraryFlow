## 1. Environment variables

## 2. Pre-deployment checklist

1. `develop` passes `npm run build`, `npm run typecheck`, and `npm test` on
   the operator's machine.
2. **Bucket name.** SPEC-002 §4 defines `book-files`, which is also the
   backend default when `SUPABASE_BOOK_BUCKET` is omitted. The live bucket,
   Render setting (if explicitly set), and `render.yaml` must use this name.
   Do not delete or migrate a legacy bucket as part of this check.
3. `FRONTEND_ORIGIN` exists in Render with the exact Netlify origin.
4. `npm run storage:verify` passed against the live bucket (recorded
   2026-11-24, 7 of 7).
5. Note the current Render deploy and the current Netlify deploy: they are the
   rollback targets (§5).
6. Take a Firestore backup (§4).

## 3. Deployment order

1. **Backup.** `npm run backup:firestore` (§4). Record the file name, document
   count, and SHA-256.
2. **Merge** the release pull request into the branch Render and Netlify
   deploy from.
3. **Render.** Wait until the deploy shows `Live`. Render checks
   `healthCheckPath: /health`; a deploy that fails the health check is not
   promoted and the previous version keeps serving.
4. **Netlify.** Wait until the deploy shows `Published`.
5. **Automated checks** from any machine, no credentials needed:

   ```bash
   npm run deploy:check -- https://<service>.onrender.com https://<site>.netlify.app
   ```

   It checks, and prints PASS or FAIL for each:

   | ID | Check |
   |---|---|
   | TC-S2-053 | `GET /health` returns 200 `HealthResponse` without authentication (waits up to 90 s for a sleeping instance) |
   | TC-S2-054 | The Netlify origin receives `Access-Control-Allow-Origin` with its exact value |
   | TC-S2-054 | A preflight from the Netlify origin succeeds |
   | TC-S2-054 | An untrusted origin receives no allow header |
   | TC-S2-053 | A protected route answers 401 `AUTH_REQUIRED` without a token |
   | TC-S2-058 | The Netlify site serves the application |
   | TC-S2-056 | The published JavaScript, including lazy chunks, contains no server secret names or values |

6. **Manual round trip (TC-S2-058).** Open the Netlify site in a private
   window, sign in as a reader, open the publisher application status page,
   and submit or view an application. In the browser developer tools
   (Network), confirm the requests go to the Render URL and return 2xx without
   CORS errors.
7. **Netlify variables (TC-S2-056).** In Netlify → Site configuration →
   Environment variables, confirm only the §1 names exist.

## 4. Backup

```bash
npm run backup:firestore
npm run backup:firestore -- --out D:\LibraryFlowBackups
```

- Reads `FIREBASE_PROJECT_ID`, `FIREBASE_CLIENT_EMAIL`, and
  `FIREBASE_PRIVATE_KEY` from `.env`. Read-only: it never writes to
  Firestore.
- Exports every collection and subcollection, 500 documents per request, to
  `backups/firestore-<project>-<timestamp>.json`. The `backups/` folder is
  git-ignored. A file is never overwritten.
- Prints the file path, the document count per collection, and a SHA-256
  checksum. Record those three in the evidence, never the file itself.
- The file contains personal data. Keep it on the operator's machine or a
  private drive, never in the repository or chat.
- Firestore free tier allows 50,000 reads per day; one backup costs one read
  per document.
- Supabase book files are not part of this backup. They are covered by the
  private bucket and the deletion jobs (S2-T08).
- Restore is planned in Sprint 3 (`S3-T09`). Until then, a data problem is
  handled by reading the backup and correcting records manually with the
  team.

## 5. Rollback

A code rollback does not change Firestore or Supabase data. Use the backup
(§4) for data questions.

### Render (backend)

1. Render dashboard → `libraryflow-api` → **Events** (or **Deploys**).
2. Find the last deploy marked `Live` before the failing one.
3. Choose **Rollback to this deploy** and confirm.
4. Run `npm run deploy:check` again; `/health` must return 200.
5. Render pauses auto-deploys after a manual rollback. Re-enable them after
   the fix is merged.

### Netlify (frontend)

1. Netlify → the site → **Deploys**.
2. Open the last good deploy and choose **Publish deploy**.
3. Run `npm run deploy:check` again.
4. Netlify locks publishing to that deploy. Choose **Unlock** after the fix is
   merged.

### Git (source of truth)

After rolling back the services, open a pull request that reverts the faulty
merge on `develop` with `git revert -m 1 <merge-commit>`. Do not force-push
shared branches.

### Rollback drill (TC-S2-057)

Once per sprint, on the team's agreement:

1. Take a backup (§4).
2. Record the current Render deploy ID.
3. Roll Render back to the previous deploy (§5), run `npm run deploy:check`,
   and confirm `/health` is 200.
4. Roll forward to the current deploy and run `npm run deploy:check` again.
5. Run a second backup and compare document counts with the first: they must
   match, showing no data loss.

## 6. Monitoring

| What | Where | Action |
|---|---|---|
| Health | Render automatic health checks on `/health`; `npm run deploy:check` after each deploy | Failed check: inspect logs, roll back (§5) |
| Backend errors | Render → Logs. Search `[book-files]`, `INTERNAL_ERROR`, `CorsConfigurationError` | `CorsConfigurationError` at startup means `FRONTEND_ORIGIN` is missing or invalid |
| Cold starts | Render free instances sleep after inactivity; the first request can take about a minute | Expected on the free plan; `deploy:check` waits 90 s |
| Frontend build | Netlify → Deploys → build log | Secret scanning failures: see §1 |
| Storage | Supabase → Storage and project usage | Unexpected public objects or growth: run `npm run storage:verify` |
| Firestore and Auth | Firebase console → Usage | Watch the daily read quota, especially after backups |

Logs never contain signed URLs, tokens, or keys (SPEC-002 §4.1). If one
appears, treat it as an incident: rotate the key and report it to the team.

## 7. Troubleshooting

| Symptom | Cause | Fix |
|---|---|---|
| Render deploy fails at startup with `FRONTEND_ORIGIN is required` | Missing variable after the S2-T07 rename | Add `FRONTEND_ORIGIN` (§1) and redeploy |
| Browser shows a CORS error | `FRONTEND_ORIGIN` does not match the Netlify origin exactly | Copy the origin from the address bar, without path or trailing `/` |
| Book upload or download answers 500 | Storage variables missing, or `SUPABASE_BOOK_BUCKET` names a bucket that does not exist | Check §1 and §2; run `npm run storage:verify` |
| Backend reports `partially configured` | Only one of `SUPABASE_URL` and `SUPABASE_SERVICE_ROLE_KEY` is set | Set both, or neither for local mode |
| `deploy:check` times out on health | Instance still waking up or crashed | Check Render logs; run again |
